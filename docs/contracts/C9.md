## 1. Scope

Fixture manifest schema, fixture lifecycle, and the four Phase-0 metrics (concept §14): per-page SSIM,
page-count delta, feature-retention assertions, text-extraction F1 — each defined precisely enough that
a Python harness and a Rust binary must agree on identical inputs.

## 2. Fixture lifecycle

States are derived from artifacts, not stored in the manifest:

| State | Condition | Actor |
|---|---|---|
| `draft` | manifest validates against schema; `sha256: null`; no blob | generator author (HAR-02) |
| `generated` / `curated` | blob exists, sha256 recorded in manifest & matches bytes; reference text present | HAR-02 / HAR-01 |
| `rendered` | candidate render exists in harness cache for each `(engine, dpi)` in `render{}` | HAR-05 |
| `golden-approved` | human approval of renders (HAR-05); record `(fixture sha256, engine id+version, fontset_hash, dpi)` written to content-addressed approved store | owner + 1 reviewer |
| `rejected` | terminal; reason in `notes` | reviewer |

Golden key = content hash of the approved raster set. A new golden is required whenever fixture
sha256, engine version, or `fontset_hash` (INV-4) changes — old goldens stay queryable for upgrade
diffs (HAR-08).

## 3. Versioning

- `schema_version` (integer, starts at `1`) in every manifest; the JSON Schema is the normative shape.
- Additive field changes → `schema_version` unchanged + contract minor bump; breaking changes →
  `schema_version` bump + migration script + all manifests migrated in one commit.
- C9 itself versions semver independently of the workspace (plan §4); harness and binary must
  accept every `schema_version` ≤ current minus deprecated-minor.

## 4. Metric — per-page SSIM vs golden

| Parameter | Normative value |
|---|---|
| Input | 8-bit rasters straight from `pdftoppm -r 150 -gray` (no re-encoding, no resizing); candidate and golden must share engine build + `fontset_hash` |
| Colorspace | grayscale (as emitted by `-gray`) |
| Resolution | **150 DPI** (D12 master resolution) |
| Window | **11×11 Gaussian, σ = 1.5**, slide/trim both images to common per-axis minimum dimension if sizes differ |
| Constants | `c1 = (0.01·255)²`, `c2 = (0.03·255)²`, `data_range = 255` |
| Page alignment | by page index; aligned count `n = min(pages_candidate, pages_golden)` |
| Aggregate | `ssim_mean = arithmetic mean of per-page SSIM over the n aligned pages`; unaligned tail not scored |
| Reference impl | `skimage.metrics.structural_similarity(..., gaussian_weights=True, use_sample_covariance=False, data_range=255)` — flags frozen in HAR-04 |

## 5. Metric — page-count delta

`page_delta = pages(candidate) − pages(golden)` (signed; also reported `|page_delta|`).
PASS iff `page_delta = 0`. Fixtures with known pagination instability declare tolerance via
`expected.page_count_min/max`; PASS iff `golden_pages + page_delta ∈ [min, max]`. Golden page count is
the measured approved value, never a generation-time guess (PLAN §4).

## 6. Metric — feature-retention assertions

For each `key` in the manifest `features{}` map, count occurrences in the package before and after
the operation under test (edit round-trip, or LO round-trip for baseline):

| key | XPath (namespaced count `//`) | Part |
|---|---|---|
| `w:tbl` | `//w:tbl` | `word/document.xml` (w = `http://schemas.openxmlformats.org/wordprocessingml/2006/main`) |
| `w:drawing` | `//w:drawing` | same |
| `w:fldSimple` | `//w:fldSimple` | same |
| `w:comment` | `//w:comment` | `word/comments.xml` + `//w:commentReference` in `document.xml` (reported as pair) |
| `table:table` / `draw:frame` / `text:field` / `office:annotation` | ODF equivalents (table 1.0 / drawing 1.0 / text 1.0 / office 1.0 ns) | `content.xml` |

Semantics: expected count = `features[key]`. PASS iff `count_after == features[key]` for **all** keys
(exact match). A `count_after != count_before` is a retention report entry even when both equal expected.
Intentional feature drop requires a manifest amendment (new fixture `schema_version` or new fixture id) —
never a metric threshold loosening.

## 7. Metric — text-extraction F1

- Reference: `corpus/reference/<id>.txt` (authored for generated fixtures; approved extraction for curated).
- Candidate: text layer of the rendered PDF (`pdftotext`, no `-layout`) or adapter extraction, per run config.
- **Tokenization:** NFC-normalize, map every Unicode whitespace codepoint (incl. U+00A0) to space,
  collapse runs, split; token = maximal non-whitespace run; case-sensitive; punctuation attaches to
  the adjacent token (no punctuation stripping). Tokens are a **multiset** (bag of words) — order
  is not scored (order errors surface via page-count delta + SSIM).
- `P = |common|/|candidate|`, `R = |common|/|reference|`, `F1 = 2PR/(P+R)`; `F1 = 1.0` iff both sides
  empty; `F1 = 0.0` iff exactly one side empty.

## 8. SSIM parity: harness ↔ binary

LIN-06 (Rust perceptual diff) must agree with the HAR-04 Python reference on **identical input raster
bytes** (same golden/candidate page pairs, same §4 parameters). Parity check = max absolute deviation
`max |ssim_py − ssim_rs|` over the full golden corpus.

**ε_parity := TBD-1 (measured).** The epsilon is set from the measured deviation at LIN-06 landing and
recorded in the concept §17 verification log by the owner — this contract deliberately does **not**
invent a number. Until TBD-1 lands, no CI gate uses a hardcoded epsilon. Parity failures block the
LIN-06 task, not the metric definitions above.

## 9. Manifest

Normative schema: `corpus/schema/fixture.schema.json` (JSON Schema draft 2020-12).
Field list: `schema_version`, `id`, `title`, `source`, `generator{name,version}`,
`origin{source,license,url}`, `format`, `categories[]`, `features{}`, `reference_text`,
`expected{page_count_min,page_count_max}`, `render{dpis[],engines[]}`, `notes`, `sha256`.

## 10. Implementation resolutions (normative, from HAR-04; ref impl `harness/metrics/`)

1. **Dimension mismatch:** trim to per-axis common minimum (§4) and score; entry flagged `size_mismatch`.
2. **Missing tail pages:** reported as `{ssim: 0.0, flags: ["missing"]}`, excluded from `min`/`mean`
   (consistent with §4 "unaligned tail not scored").
3. **Complex fields:** `w:instrText` key counts `fldChar begin…end` groups containing instrText
   (innermost attribution); reported alongside `w:fldSimple`.
4. **Comments:** reported as the pair `w:comment` (comments part) + `w:commentReference` (document.xml).
5. **ODF notes:** both `text:note` and `text:field` counted (§6 row lists `text:field`; `text:note` added).
6. **CJK tokenization (amends §7):** Han ideographs & kana tokenize **one char = one token**
   (U+4E00–9FFF, U+3400–4DBF, U+F900–FAFF, U+3040–30FF; exact ranges in `metrics/text.py`);
   all other scripts per §7.
7. **Tiny rasters:** < 11×11 px → `image_too_small` error; window params never auto-shrink.
8. **Page order:** natural sort of raster filenames within a directory.
9. **Non-gray input:** converted to grayscale, flagged `converted_to_grayscale`; normative rasters are
   still produced with `pdftoppm -gray`.
10. **No SSIM clamping** (keeps the Rust port honest).
11. **Retention PASS** = `before == after` for every tracked key; matching manifest `features{}`
    expectations is a separate caller-side assertion.
12. **Diagnostics excluded:** `format`, `part_count`, `uncompressed_bytes` never participate in retention.
13. **P/R with an empty side:** 0.0 (F1 per §7).
