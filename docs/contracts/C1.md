# C1 — Intermediate Representation Contract

| | |
|---|---|
| Owner | CORE |
| Consumers | all adapters, engines, lint, MCP, CLI |
| Freeze | **v1.0.0 at P1-03 landing**; additive only after (contract minor bump) |
| Version | 1.0.0-draft |

## 1. Scope
Defines the canonical intermediate representation (IR) for all document families processed by stichos.

## 2. Versioning
- `IR_VERSION = "1.0.0"` (constant in gp-core)
- Each top-level document type carries `ir_version` field
- Additive changes → contract minor bump; breaking → schema_version bump
- Migration path via `IR_VERSION_MIGRATION` field

## 3. Document families
### 3.1 Document (Word-like)
- Top-level: `Document` with ir_version, sections[], headers[], footers[]
- Section: id, kind (body/header/footer/footnotes/endnotes), items[], headers[], footers[], footnotes[], endnotes[]
- SectionItem: Paragraph, Table, Drawing, List
- Paragraph: id, runs[], page_number?, style_name?
- Run: id, text, bold?, italic?, font_name?, font_size_pt?, underline?, strikethrough?
- Table: id, rows[]
- Row: cells[]
- Cell: id, contents[], colspan?, rowspan?
- Drawing: id, mime_type, data, bbox_pt?
- List: id, kind (bullet/numbered/other), items[]
- ListItem: id, content[], level
- Header: id, content[], is_even_page
- Footer: id, content[], is_even_page
- Footnote: id, content[], reference_id?
- Endnote: id, content[]

### 3.2 Spreadsheet (Excel-like)
- Top-level: `Spreadsheet` with ir_version, sheets[]
- Sheet: id, name, rows[], merged_ranges[], header_row?, footer_row?
- SheetRow: cells[]
- SheetCell: id, row, col, formula?, cached_value?, style?

### 3.3 Presentation (PowerPoint-like)
- Top-level: `Presentation` with ir_version, slides[], layouts[], masters[]
- Slide: id, layout_ref?, notes?, background_color?, elements[]
- SlideElement: Text, Drawing, Table, Image, Group
- Layout: id, name
- Master: id, name, layout_refs[]

### 3.4 PDF
- Top-level: `PdfDocument` with ir_version, pages[], metadata?, annotations?, outline?, form_fields?, tagged_structure?
- PdfPage: id, page_number, width_pt, height_pt, rotation?, text_with_bboxes[]
- PdfAnnotation: id, subtype, rect, contents?, color?, border_style?, modified_date?
- PdfOutlineItem: title, page, children[]
- PdfFormField: id, name, field_type, value?, read_only, required, flags?
- PdfMetadata: title?, author?, subject?, creator?, producer?, creation_date?, modification_date?
- TaggedNode: tag, alt_text?, children[]

## 4. Unified IR
- `IRDocument` wraps any document family: { ir_version, doc?, spreadsheet?, presentation?, pdf? }
- Exactly one of the family fields is populated per IRDocument

## 5. Element IDs
- Every element has an `id` field (ElementId = Uuid)
- IDs are content-anchored (derived, not random) — see C2

## 6. Serde requirements
- All types must serialize/deserialize correctly
- Optional fields use `skip_serializing_if`
- Enums use `tag` for JSON discrimination
- All types implement Debug + Clone + PartialEq + Serialize + Deserialize

## 7. Conformance
- C1 contract test suite (in gp-core tests) verifies all of the above
- No ad-hoc struct definitions — all IR types flow through gp-core
