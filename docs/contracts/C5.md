# C5 — Engine API Contract

| Field | Value |
|---|---|
| Owner | ENG |
| Consumers | doctor, render, MCP, CLI |
| Freeze | **v1.0.0 at P1-25 landing** |
| Version | 1.0.0-draft |

## 1. Scope

Defines the engine API: id, version, fontset_hash, convert(), info(), capability matrix, and rendered_by provenance.

## 2. Engine trait

The `Engine` trait is defined in `gp-core::traits::Engine` and extended by `EngineExt` in `gp-core::traits`:

- `engine_id()` — unique identifier for the engine (e.g. `"libreoffice"`, `"pandoc"`, `"ms-office"`)
- `version()` — version string of the engine, `None` if unknown
- `fontset_hash()` — deterministic hash of the font set used for rendering (INV-4 render cache key)
- `is_available()` — runtime availability check (binary exists, can be spawned)
- `can_convert(source, target)` — can this engine convert between the given formats?
- `convert(input, source, target)` — convert bytes between formats, returns output bytes or diagnostics
- `info()` — full engine info including capabilities (via `EngineExt`)
- `supported_conversions()` — list of `(source, target)` pairs the engine can handle (via `EngineExt`)

## 3. Engine identifiers

Constants are defined in `engines` crate:

- `LIBREOFFICE_ENGINE_ID = "libreoffice"`
- `PANDOC_ENGINE_ID = "pandoc"`
- `MSOFFICE_ENGINE_ID = "ms-office"`

## 4. Capability matrix

Aggregates capabilities across all discovered engines into a single `CapabilityMatrix`. Each engine entry contains its `capabilities` list of `CapabilityEntry` items (source, target, works).

Built via `engines::capability::build_capability_matrix(engines: &[&dyn Engine])`.

Used by the `doctor` tool to report real engine capabilities.

## 5. RenderedBy

Every response includes a `rendered_by` field of type `RendererInfo` with:
- `engine_id` — which engine produced the output
- `version` — engine version string
- `fontset_hash` — deterministic hash of the font set

Built via `engines::build_rendered_by(engine: &dyn Engine)`.

If no engine is available: `rendered_by` is `None` and `visual_feedback` should be `"unavailable"`.

## 6. Mock engine

`engines::mock::MockEngine` provides a configurable engine for testing without real engine software.

Fields: `id`, `version`, `fontset_hash`, `available`, `conversions`.

Implements both `Engine` and `EngineExt` traits.

## 7. EngineInfo

Defined in `gp-core::traits::EngineInfo`:

```rust
pub struct EngineInfo {
    pub engine_id: String,
    pub version: Option<String>,
    pub fontset_hash: Option<String>,
    pub is_available: bool,
    pub capabilities: Vec<CapabilityEntry>,
}
```

## 8. Fidelity budget integration

The `rendered_by` field in `FidelityBudget` (from `gp-core::fidelity`) carries the engine provenance. The fidelity budget builder has a `.rendered_with(engine_id, version, fontset_hash)` method.

## 9. Diagnostics

Engine diagnostics use codes from the ENG prefix:

- `ENG-E-001` — engine not found
- `ENG-E-002` — engine timeout
- `ENG-W-001` — engine version mismatch

See `gp-core::diagnostics` for the full registry.
