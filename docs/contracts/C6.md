# C6 — Undo Journal Format

| | |
|---|---|
| Owner | CORE |
| Consumers | PAT, API (apply, diff, revert) |
| Freeze | **v1.0.0 at M2** |
| Version | 1.0.0-draft |

## 1. Scope

Defines the undo journal format for the stichos content-addressed store. The journal records
every mutation as an immutable sidecar entry with pre/post content hashes, enabling a single
`revert` primitive that returns a byte-identical original.

Governing principles (P6 / INV-3):
- **Never write in place** — originals are immutable in the store.
- Every mutation is journaled as an append-only entry.
- A revert returns a byte-identical original — no "reverse edit" computation.

## 2. Journal entry format

Each journal entry is a self-contained JSON object stored as a separate file in the session
directory. The filename is the content-addressed entry ID (SHA-256 of the entry).

```json
{
  "version": "1.0.0",
  "entry_id": "<sha256 of this object>",
  "parent_id": "<sha256 of previous entry, null for first>",
  "timestamp": "2026-09-10T12:00:00Z",
  "action": "insert | replace | delete | style | tracked-change",
  "source_doc_id": "<content hash of the source document before this edit>",
  "target_doc_id": "<content hash of the document after this edit>",
  "target_doc_path": "/path/to/modified.docx",
  "ir_patch": "<ir_version>|<base64-encoded IR unified diff>",
  "xml_diffs": [
    {
      "part": "word/document.xml",
      "before_hash": "<sha256>",
      "after_hash": "<sha256>"
    }
  ],
  "tracked_change": {
    "author": "agent-id",
    "comment": "structural edit description",
    "accept_id": "<optional: if set, this creates a tracked change instead of direct apply>"
  },
  "fidelity_budget": {
    "dropped_features": [],
    "part_warnings": [],
    "unknown_parts": [],
    "confidence": 1.0,
    "rendered_by": {
      "engine_id": "libreoffice",
      "version": "26.2.5",
      "fontset_hash": "<sha256>"
    }
  },
  "diagnostics": []
}
```

## 3. Session directory layout

```
~/.stichos/sessions/<session-id>/
  store/                          # content-addressed blob store (immutable)
    <sha256-of-doc>               # original and all document versions
  journal/
    <sha256-of-entry-1>.json     # first entry (parent_id = null)
    <sha256-of-entry-2>.json     # second entry (parent_id = sha256-of-entry-1)
    ...
  head.json                       # current head entry ID (last applied)
  state.json                      # session state: { session_id, created_at, head_id }
```

### 3.1 Content-addressed store

- Keys are SHA-256 hex of the document bytes.
- Each key maps to exactly one blob (append-only, never overwritten).
- The store is the single source of truth for document content at any point in time.

### 3.2 Journal chain

- Entries form a linear chain: each entry has `parent_id` pointing to the previous entry.
- The chain starts with `parent_id = null` for the first entry.
- `head.json` always points to the latest applied entry.
- Revert = read the parent entry's document blob, copy it to the store under its own hash.

### 3.3 Session state

`state.json` tracks:
```json
{
  "session_id": "<uuid>",
  "created_at": "ISO-8601 timestamp",
  "head_id": "<entry_id of latest applied entry>"
}
```

## 4. Action types

| Action | Description |
|--------|-------------|
| `insert` | Insert a new element at a stable path |
| `replace` | Replace an existing element at a stable path |
| `delete` | Remove an existing element at a stable path |
| `style` | Change styling without structural impact |
| `tracked-change` | Create a tracked change for human review (Phase 2) |

## 5. IR patch format

The `ir_patch` field is a pipe-delimited string:

```
<ir_version>|<base64-encoded-ir-unified-diff>
```

The IR unified diff format:

```
--- <section-path>
+++ <section-path>
<ops>
```

Where `<ops>` is a sequence of operations:
- `I <path> <content-json>` — insert at path
- `R <path> <old-content-json> <new-content-json>` — replace
- `D <path>` — delete

## 6. Surgical patch invariant (INV-1)

Every journal entry MUST satisfy:
- All `xml_diffs` parts not listed are byte-identical between `source_doc_id` and `target_doc_id`.
- The `ir_patch` applies cleanly to the document state at `parent_id`.
- The `target_doc_id` equals `sha256(bytes_of(source_doc_id) with ir_patch_applied)`.

## 7. Revert primitive

```
revert(session_id) -> document_bytes
```

1. Read `state.json` to get the current `head_id`.
2. Read the entry at `head_id`.
3. If `parent_id` is `null`, the journal is at its root — revert is a no-op (return the original document blob).
4. Otherwise, copy the document blob referenced by `parent_id` as the new head.
5. Update `state.json` with the new `head_id`.
6. Return the document blob.

The returned document bytes are guaranteed byte-identical to the state at the parent entry.

## 8. Tracked changes (Phase 2)

When `action` is `tracked-change`:
- The edit is NOT applied directly to the document.
- A `tracked_change` block records the author, comment, and the patch to be applied on accept.
- The `accept_id` field, when set, creates a new journal entry that applies the patch.
- The `reject_id` field, when set, discards the tracked change without applying it.
- This enables the human-in-the-loop workflow (P7 / D7).

## 9. Conformance tests

The following tests must pass in `gp-core`:

1. **Chain integrity:** For a 10-entry journal, verify each entry's `parent_id` matches the
   previous entry's `entry_id`.
2. **Revert byte-identical:** After 5 edits, revert to entry 0 — the returned bytes must match
   the original document exactly.
3. **Surgical invariant:** Verify that unlisted parts are byte-identical between source and target.
4. **IR patch round-trip:** Apply an IR patch to a document state, then reverse it — the original
   state is recovered.
5. **Head consistency:** After each journal write, verify `head.json` matches the latest entry ID.
6. **Content-addressed uniqueness:** No two distinct document states map to the same store key.
7. **Tracked change isolation:** A `tracked-change` entry does not modify the document; only an
   accept entry does.
