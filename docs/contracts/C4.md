# C4 — Read Response Shape Contract

| | |
|---|---|
| Owner | CORE |
| Consumers | MCP, CLI, lint |
| Freeze | **v1.0.0 at P1-06 landing**; additive only after |
| Version | 1.0.0-draft |

## 1. Scope
Defines the shape of every read response: fidelity budget, provenance, and confidence.

## 2. Read response shape
Every read response (from any adapter) MUST include:

```json
{
  "fidelity_budget": {
    "dropped_features": [{"feature": "...", "reason": "...", "count": N}],
    "part_warnings": [{"part": "...", "message": "..."}],
    "unknown_parts": ["part/path.xml"],
    "rendered_by": {"engine_id": "...", "version": "...", "fontset_hash": "..."},
    "confidence": 0.95,
    "has_potentially_unsafe": false
  }
}
```

## 3. Provenance (INV-2)
- Every response names its engine + version, or `rendered_by` is null
- `rendered_by` field is always present in the JSON structure (may be null)
- Engine identifiers follow the convention: `<tool>-<variant>` (e.g. "libreoffice", "pandoc")

## 4. Fidelity budget algebra
- **Merge is commutative**: merge(a, b) == merge(b, a) (structurally equal on all fields)
- **Merge is associative**: merge(merge(a, b), c) == merge(a, merge(b, c))
- **Idempotent**: merge(a, a) == a (after normalization)
- **Confidence** is pessimistic (minimum of both)
- **Dropped features** deduplicated by (feature, reason) pair
- **Part warnings** deduplicated by part name
- **Unknown parts** deduplicated
- **Unsafe content** flagged with OR semantics
- **Rendered by**: prefer non-None; when both are Some, keep the left (self)

## 5. Confidence
- Range: [0.0, 1.0]
- 1.0 = full fidelity, no drops
- < 1.0 = features lost or degraded
- `summary_score()` provides a single-number summary: `(max - total) / max` where total includes dropped feature counts, warnings, and unknown parts
- `is_good()` returns true when confidence > 0.8 and no unsafe content

## 6. Conformance
- Algebra tests: merge, idempotence, commutativity, associativity
- JSON shape test: all fields present in serialized output
- INV-2 test: rendered_by always present (may be null)
- Builder tests: fluent API chain works end-to-end
- Clamping: confidence values outside [0.0, 1.0] are clamped
