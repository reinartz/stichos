## Scope

This contract defines the tool schemas, argument shapes, return types, and behavioral
guarantees for the stichos MCP + CLI tool surface. v1.0.0 froze the Phase-1 read-only surface;
M2 added the edit family (v1.1.0) and M3 the creation/sandbox/update family (v1.2.0), both
**additive-only**. Phase 4 will add the revision-review family at v1.3.0 (see
[`../phase4-concept.md`](../phase4-concept.md)).

## Tools (v1.0.0, frozen M1)

### inspect_document

- **Description:** Extract structure, element IDs, coordinates manifest, and fidelity budget.
- **Args:** `path: string` (required), `format: string` (optional, inferred from extension)
- **Returns:** `{ structure, ids, coordinates, fidelity_budget, diagnostics }`
- **Idempotent:** Yes
- **Dry-run:** N/A (read-only)

### render_document

- **Description:** Render document to page images with layout QA.
- **Args:** `path: string` (required), `dpi: number` (default 150), `page_range: array` (optional)
- **Returns:** `{ images: [block], manifest, diagnostics }`
- **Idempotent:** Yes
- **Dry-run:** N/A

### inspect_region

- **Description:** Crop and zoom a region from a document for detailed inspection.
- **Args:** `path: string` (required), `page: number` (required), `bbox_pt: array[4]` (required), `zoom: number` (default 2.0)
- **Returns:** `{ image, coord_record, visual_tokens }`
- **Idempotent:** Yes
- **Budget:** ~600 tokens per crop

### diff_documents

- **Description:** Compare two documents and report structural and visual differences.
- **Args:** `path_a: string` (required), `path_b: string` (required), `format: string` (optional), `max_ops: number` (optional)
- **Returns:** `{ ir_diff, xml_diffs, diagnostics }`
- **Idempotent:** Yes

### doctor

- **Description:** Probe the host: check engine availability and render test fixtures
  (incl. chromium/pandoc/typst authoring rows since M3).
- **Args:** None (optional `--json` flag)
- **Returns:** `{ engines, fonts, system_info, capability_matrix }`
- **Idempotent:** Yes

### serve

- **Description:** Start the MCP transport server (stdio or HTTP).
- **Args:** `transport: string` (default "stdio"), `port: number` (default 8731)
- **Returns:** N/A (daemon)
- **Idempotent:** Yes

## Tools (v1.1.0 additive, M2 — surgical edit)

Exact arg/return schemas live in `crates/mcp/src/spec.rs`; key guarantees:

- **`apply_patch`** `{ path, ops[], dry_run, format, session_id, direct, author }` — routes IR patch
  ops through the patch executor (OOXML/ODF/PDF). Non-idempotent. `dry_run` writes nothing (P3).
  `direct=false` lands docx edits as tracked revisions (D7). Journaled (INV-3), budget on response (INV-2).
- **`edit_text` / `edit_cell` / `edit_structure`** — sugar over `apply_patch` for element-id-targeted
  edits (`element_id` per C2). Idempotent given unchanged inputs.
- **`annotate_pages`** — numbered lint boxes on rendered pages; returns marked+clean pairs + legend.
- **`revert_document`** `{ path, steps, session_id }` — revert last N journal entries; byte-identical
  original restored (INV-3). Non-idempotent.
- **`journal`** `{ path, session_id }` — list journal entries (C6). Read-only.

## Tools (v1.2.0 additive, M3 — creation, sandbox, update)

- **`create_document`** `{ source_type, format, content, template, dry_run, target, author, direct }`
  — four paths (pandoc / chromium / typst / native). `dry_run` returns preview render + IR, writes
  nothing. `target` + `direct=false` = create-as-revisions (`w:ins`/`w:del`) into an existing docx.
  Response carries the full envelope: new doc id, fidelity budget, rendered pages, lint manifest,
  `rendered_by` (INV-2). Non-idempotent.
- **`script_tool`** `{ script, ir? }` — sandboxed Rhai (ADR-0005, D17). Host fns scoped to
  store/IR/patch only; no fs/net/env; ops/size/depth/wall-clock limits. Any patch applied is
  journaled exactly like `apply_patch`.
- **`check_update`** `{ channel }` — GitHub Releases channel probe (ADR-0006, G4). Verify metadata
  only; the CLI `stichos update` performs verify-before-swap with rollback; opt-in, explicit.

## Behavioral Guarantees

### Idempotency

Read tools are idempotent: same args ⇒ same result (document and environment unchanged).
Mutation tools (`apply_patch`, `create_document`, `script_tool`, `revert_document`) are
non-idempotent and journaled; `dry_run` is side-effect-free on all tools that expose it.

### Versioning

- Per-tool `schema_version` as in the matrix above; the surface version is the max across tools.
- Deprecated tools are marked with `"deprecated": true` and a `deprecation_notice` field.
- Breaking changes require a **minor** version bump.
- Additive changes (new fields, new optional args) are allowed in patch versions.
- v1.0.0 → v1.1.0 → v1.2.0 verified additive-only (no removals, no arg retyping; checked at each
  phase gate via schema matrix + CHANGELOG scan).

### Error Handling

- All errors use C3 diagnostic codes (LIN-*, MCP-*, GP-*, ODF-*, PDF-*, ENG-*, RHI-*)
- No ad-hoc error codes in user-visible output
- Errors include `is_error: true` and a diagnostic list

### Payload Budget (C8)

- Maximum 20 image blocks per response
- Maximum 2000 pixels per side
- Visual tokens: `⌈w/28⌉ × ⌈h/28⌉`

### Provenance (INV-2)

Every response includes:

- `rendered_by: string` — engine ID + version, or `"unavailable"`
- `diagnostics: [...]` — C3-coded diagnostics

## Frozen

v1.0.0 frozen at M1. Additive revisions only (v1.1.0 at M2, v1.2.0 at M3 — verified). Breaking
changes would require a new contract major and a decision-log entry. Phase 4 reserves v1.3.0 for
the revision-review family (`list_revisions`, `accept_revisions`, `reject_revisions`) per
[`../phase4-plan.md`](../phase4-plan.md) P4-08.
